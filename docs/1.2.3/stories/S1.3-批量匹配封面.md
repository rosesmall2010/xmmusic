# S1.3 批量匹配封面（仅无有效封面）

**Epic**: 1 — 匹配封面  
**优先级**: P0  
**状态**: done  
**依赖**: S1.1  
**估算**: 1～1.5 天  

---

## 用户故事

作为用户，我希望一键为所有**没有有效封面**的本地歌曲自动匹配封面；过程可看进度、可取消；结束只看汇总，并能分辨写进文件还是仅更新库。

---

## 验收标准

1. 本地音乐工具栏「批量匹配封面」，与「批量匹配歌词」并列。  
2. 范围：无有效封面（空路径或文件缺失）；无目标时按钮禁用 + tips。  
3. 自动匹配：先搜标签**歌名** ≥50；不足再搜标签**歌手** ≥50；仍未命中则用文件名推测歌名/歌手（与已搜相同则跳过）再试，仍无 ≥50 则放弃；有有效封面一律跳过。  
4. 进度/取消/离开再回可见（对齐 `lyricsMatch` store）。  
5. 汇总含：成功、失败、跳过、取消；成功中区分 **writtenToFile** / **dbOnly**（非 MP3）。  
6. 与批量歌词**互斥**：一方 `running` 时另一方禁用。  
7. i18n + `npm run build` + CHANGELOG。  

---

## 实现要点

- `stores/coverMatch.ts`；IPC batch/progress/cancel。  
- 并发与间隔对齐歌词批量（最多 3 路）。  
- 写入门槛与 S1.1 自动策略一致：标签歌名 ≥50 → 歌手 ≥50 → 文件名推测差异词再试。  

---

## 非目标

- 批量强制覆盖有效封面  
- 汇总点进手选  

---

## 测试建议

- 歌词批量进行中封面按钮禁用。  
- 取消后已写入保留。
