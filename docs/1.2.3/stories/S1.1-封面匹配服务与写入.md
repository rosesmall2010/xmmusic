# S1.1 封面匹配服务与写入链路

**Epic**: 1 — 匹配封面  
**优先级**: P0  
**状态**: done  
**完成日期**: 2026-09-16  
**依赖**: 无  

---

## 用户故事

作为本地音乐用户，系统应能根据歌名/歌手在线找到专辑封面，并按「改 Tag」规则写入（MP3 写文件+库，非 MP3 只更新库）。

---

## 验收标准

1. 主进程服务：自动选最优（≥75）；列出候选（≥35）；应用指定候选。  
2. **图源**（缺一不可）：  
   - 复用歌词侧 `SEARCH_APIS` 搜歌；  
   - 从结果解析封面 URL（兼容 `album.picUrl` / `al.picUrl` 等）；  
   - **无 URL 时用 id 调详情接口补图**；仍无则该候选不可用 / 匹配失败，错误可区分「无封面地址」。  
   - 不得假设 `lyricsMatchService` 已映射 `picUrl`（当前未映射）。  
3. **有效封面判定**：`coverPath` 非空且 `accessSync(..., R_OK)` 可读 → 有封面；否则无封面。`force=false` 且有有效封面 → `skipped_has_cover`。  
4. 下载：原图不缩放；**超时**、**非图片 Content-Type**、**超过大小上限（建议 15MB）** → 失败且不写文件/不更新 DB。  
5. 缓存写入 `userData/covers/`（对齐 `fileScanner.extractCover`）；重新匹配覆盖或换名并更新 `cover_path`，避免旧图残留显示。  
6. 应用封面：  
   - `/\.mp3$/i.test(filePath)`：先成功写 APIC（`metadataEditor.updateMetadata`），再更新 DB；写文件失败则 **不更新** DB。  
   - 非 MP3：只更新缓存 + DB，结果带 `fileNotUpdated: true`。  
7. IPC：`match-cover`、`list-cover-candidates`、`apply-cover-candidate`；类型在 `src/shared/types/coverMatch.ts`。  
8. 返回新 `coverPath`；可供 UI 刷新播放中封面。  
9. `npm run build` 通过；CHANGELOG `[1.2.3]` 追加本 Story 要点。  

---

## 实现要点

- 新建 `coverMatchService.ts`、`coverMatch.ts` 类型。  
- 相似度逻辑可抽共享或复制歌词侧常量（75 / 35）。  
- 批量取消钩子预留（`shouldAbort`）。  
- 抽检：用 `music-metadata` 读回 APIC 或手工外部播放器验证。

## 非目标

## 测试建议

- 无 picUrl 仅靠详情补图；详情也无。  
- 失效 `coverPath` 视为无封面。  
- MP3 写失败不改 DB；FLAC 只改库。  
- 超大/超时 URL。
