## 1. 匹配封面并写 Tag

### 1.1 目标

为本地歌曲在线匹配专辑封面；写入规则与「改 Tag」一致。

### 1.2 写入规则

| 格式 | 行为 |
|------|------|
| **MP3** | 写回文件 ID3 封面（APIC）+ 更新数据库 `cover_path` + 应用内封面缓存 |
| **非 MP3** | 只更新数据库 / 应用内封面缓存，**不改文件**，并提示用户 |

- **MP3 判定**：与改 Tag 一致——`/\.mp3$/i.test(filePath)`（见 `NewTagInfoModal`）。
- 复用：`metadataEditor.updateMetadata(..., { coverPath })`。
- 写文件失败时：**不得**把 DB `cover_path` 更新为未成功写入的状态；返回可区分错误（只读、写 ID3 失败等）。

### 1.3 有封面 / 无封面

| 状态 | 判定 | 批量 | 单曲 |
|------|------|------|------|
| **无封面** | `coverPath` 为空/空白，**或**路径指向的文件不存在/不可读 | ✅ 可批量 | ✅ 匹配封面 |
| **有封面** | `coverPath` 有值 **且** 文件存在可读 | ❌ 不进批量 | ✅ 重新匹配；写入前**二次确认** |

### 1.4 图源与阈值

- **图源**：与歌词同源网易云搜索镜像（`SEARCH_APIS`）。
- **取图步骤（必须）**：
  1. 搜索歌曲结果中解析封面 URL（常见字段如 `album.picUrl` / `al.picUrl`；实现时按实际 JSON 兼容多种形态）。
  2. 若搜索结果无可用 URL：用歌曲/专辑 id 调详情接口补封面；仍无则该候选不可用。
  3. 现有 `lyricsMatchService` **未映射封面字段**，封面服务须自行扩展解析，不可假设歌词代码已有 `picUrl`。
- **批量自动**：先搜标签**歌名**，相似度 **≥ 50** 才写入；不满足再搜标签**歌手**，仍要求 **≥ 50**。仍未命中时，用文件名推测歌名/歌手（`parseFilenameForTags`）；与已搜关键词相同的维跳过，再各试一轮（仍 ≥50）；都没有则放弃。
- **手动候选列表**：分别搜标签**歌名**与**歌手**，并叠加文件名推测出的差异歌名/歌手；合并去重后**不设相似度下限**，按相似度降序展示；也可选择本地图片；由用户点选或取消。
- **写入尺寸**：**不缩放**；但须有防护——下载超时、非图片 Content-Type、单文件过大（建议上限如 15MB，超限失败并记原因，**不截断写入**）。「不限制边长」≠「无限下载」。

### 1.5 单曲交互（与匹配歌词对齐）

| 入口 | 行为 |
|------|------|
| 列表右键「匹配封面」 | **多候选选择**（可预览 / 选本地图）；标签歌名+歌手双搜，叠加文件名推测差异词，不设下限，按相似度降序 |
| 列表右键「重新匹配封面」 | 二次确认后弹候选列表；`force` 写入 |
| 全屏播放页 | **多候选选择**；策略同右键；可预览在线结果或选择本地图片后应用 / 取消 |

工具栏：**批量匹配封面** 与「批量匹配歌词」并列。

### 1.6 封面缓存

- 目录对齐扫描：`userData/covers/`（见 `fileScanner.extractCover`）。
- 文件名建议：`{fileHash 或 musicId}_cover.{ext}`；**重新匹配须覆盖**同路径或更新 `cover_path` 并避免列表仍读旧缓存（必要时改文件名或破缓存）。
- 写库成功后返回新 `coverPath`，并通知渲染进程刷新列表与当前播放封面。

### 1.7 批量失败与汇总

- 结束后**只汇总**（成功 / 失败 / 跳过 / 取消）。
- 汇总须区分：**已写文件** vs **仅更新库（非 MP3）**（计数或明细字段）。
- 一期不支持从汇总点进失败项手选。
- 与「批量匹配歌词」**互斥**：一方运行时另一方按钮禁用（或排队），避免双写竞态。

### 1.8 非目标

- 批量覆盖已有有效封面  
- 歌单封面在线匹配  
- 多图源 fallback（网易云之外）  
- 图片缩放/压缩

## 2. 拼音 / 声母搜索

### 2.1 目标

搜索支持汉字、**全拼**、**声母（首字母）**。

### 2.2 作用范围（修订）

**现状**：本地音乐页**无**独立搜索框；搜歌走**顶栏 → 搜索页**（`AppHeader` / `SearchView` / `searchMusic`）。

本期范围：

- **必须**：顶栏全局搜索走拼音/声母逻辑。  
- **必须**：凡调用同一 `searchMusic`（或共享匹配工具）的入口一并受益。  
- **不强制**：单独再做「本地音乐页搜索框」；若日后本地页加过滤，须复用同一套匹配工具。

### 2.3 匹配规则

- 字段：至少 `title` / `artist` / `album`（及现有已覆盖的 `file_name`）。
- 原文、全拼、声母任一包含查询串即命中；大小写不敏感。
- **声母**：对字段声母串做包含匹配即可（接受一定误伤；用例覆盖 `zjl` / `qt`）。
- **查询分流**：汉字/原文可继续 FTS5；拼音/声母走旁路（预计算列或内存索引），结果与 FTS **合并去重**；禁止把任意拼音字符串直接塞进 FTS `MATCH`（防语法错误）。
- 多音字：默认读音。

### 2.4 方案与工期

S2.1 动手前在 Story 内锁定方案 A（DB 预计算）或 B（内存索引）；若选 A，须含**存量回填**任务，工期按回填成本调整。

## 3. 应用内快捷键

### 3.1 决策

- **不做全局**（`ENABLE_GLOBAL_SHORTCUTS = false` 保持；注释改为产品决策说明）。
- **仅应用内**：窗口聚焦时生效。

### 3.2 覆盖窗口

- 主窗口、迷你播放器；不含桌面歌词窗。

### 3.3 默认动作与键位

| 动作 | 说明 |
|------|------|
| 播放/暂停 | **优先**普通键（推荐 `Space`，输入框聚焦时除外）；不依赖系统媒体键 |
| 上一首 / 下一首 | 普通组合键（沿用或贴近现有 mac/win 默认表中的非 Media* 项） |
| 音量加 / 音量减 | 须在 `App.vue`（及迷你）**实现 handler**（现状缺失，本迭代补齐） |
| 收藏 | 组合键；输入框聚焦时不触发 |

- **不把** `MediaPlayPause` / `MediaNextTrack` 等作为唯一默认绑定：应用内模式下许多系统不会把媒体键送给窗口。
- 设置里若仍出现历史 `toggle-window`：本期可隐藏或标明未实现，避免死键；默认动作清单不含该项。

### 3.4 输入优先

搜索框 / textarea / contenteditable 聚焦时，字母类及 Space 播停不触发。
